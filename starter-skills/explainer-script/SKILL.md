# Explainer script

Topic: $ARGUMENTS

An explainer is one person on camera making one complicated thing simple in about 2 minutes. The host's time is the constraint: the agent does the research, the script and the cut plan, so the host only reads and records. If the user has a voice or style file (a `voice.md`, past scripts, a handle to match), read it first and write in that voice.

## Steps

1. **Pin the subject.** Write the cover line as "[subject] explained" in lowercase. If the topic is too broad to explain in 2 minutes, narrow it and say how. Done when the cover line fits on one line of a phone screen.
2. **Find the raw sources.** Prefer primary sources: the company's own post, the filing, the paper, the dataset, the original clip. Note the outlet and date for each fact. Done when every fact you plan to use has a source you opened.
3. **Write the beat table**: `| # | Host says | On screen |`, 12 to 15 beats, 280 to 330 words.
   - **Beat 1** is the contrast or number that makes people stay. It is said in the first 2 seconds.
   - **Middle beats** carry one fact each. The "On screen" cell names the real visual (screenshot, clip, chart) and its source.
   - **One beat** ties the subject to the host's own work or proof, if the user has given you that proof. Never invent a result for them.
   - **The last beat** is a question viewers can answer in one line in the comments.
   - Done when the word count is in range and every number has a source.
4. **Check the facts.** Under the table, list every claim with its source, plus anything the host must confirm before recording. Done when no claim in the table is missing from the list.
5. **Make it sound spoken.** Short sentences, plain words, first person. Read it aloud in your head: anything the host would stumble on gets rewritten. Cut stock AI phrasing ("dive into", "game-changer", "it's not X, it's Y", em dashes). Done when every line is something a person would actually say.
6. **Plan the cut.** For each beat, list the visual and whether it exists yet or needs a capture. Recording advice for the host: one phone take, jump cuts are fine, read each line twice if unsure. Done when every "On screen" cue has a file or a capture task.

## Output

The beat table, the fact-check list, a one-paragraph caption (short, ends on the same question as the last beat), and the shot list. End with a numbered list of what the host must confirm or supply.

## Rules

- No fact without a source. A number you can't source gets cut or flagged, never rounded into something that sounds right.
- Use real visuals: screenshots, source clips, the host's own work. Avoid generic stock or AI-generated filler.
- Nothing gets posted by the agent. The host reviews and posts.
